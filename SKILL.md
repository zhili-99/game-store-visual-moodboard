# Game Store Visual Moodboard

Turn a folder or list of game-store images into an evidence-based written analysis and a presentation-ready PNG moodboard.

## Required outcome

Use the JSON files as working evidence. The final user-facing delivery must contain exactly these two primary artifacts:

1. A written analysis in chat or Markdown, beginning with the moodboard positioning and its explanation, then covering evidence, palette, layout, style grammar, visual formula, and conclusion.
2. A high-resolution PNG moodboard generated by `scripts/store_moodboard.py render`.

Still create a scan JSON containing image inventory, exact-duplicate groups, dimensions, and extracted colors, plus an analysis JSON following [references/analysis-schema.md](references/analysis-schema.md). Treat them as working files unless the user asks for them.

Optionally produce the contact sheet and standalone HTML wrapper when useful or requested.

The PNG must show the evidence and the reusable design system together:

- a prominent moodboard-positioning section with a one-sentence statement and explanatory description;
- category, audience feeling, emotional goal, and visual promise when the evidence supports them;
- representative screenshots with short labels;
- sample count and duplicate-removal note;
- named color swatches with HEX values, role, usage, and measured or clearly approximate share;
- genuinely distinct visual lanes, if present;
- top/middle/bottom or other meaningful composition zones;
- tone, material, lighting, camera, character, typography, and feedback language;
- one concise visual formula that another artist can apply.

## Workflow

### 1. Establish the sample gate

Resolve the exact local folder or files. Use `rg --files` for inventory when needed. Store screenshots, feature graphics, icons, and ads are different evidence types; do not mix them silently. Exclude icons unless the user asks for icon analysis.

Run the deterministic scan:

```powershell
python scripts/store_moodboard.py scan <input-folder-or-files> --out scan.json --contact-sheet contact-sheet.png
```

The scanner recursively discovers PNG, JPG, JPEG, and WEBP files, orders them naturally, removes exact duplicates by SHA-256, records duplicate groups, and extracts per-image and aggregate colors.

If there are more than 12 unique images, select a representative set that preserves meaningful visual lanes. Do not simply take the first files when versions, orientations, or campaigns differ.

### 2. Inspect the images visually

Use `view_image` on the contact sheet and on representative originals. Color extraction does not identify narrative role, material, hierarchy, or emotional tone; those require visual judgment.

Separate observations from inference:

- Observation: repeated magenta footer, white all-caps text, thick purple stroke.
- Inference: the footer acts as a brand anchor across mixed visual treatments.

Read [references/visual-analysis-rubric.md](references/visual-analysis-rubric.md) when producing a full art-direction analysis or when the visual system is ambiguous.

### 3. Author the analysis JSON

Create `analysis.json` using the schema and example in [references/analysis-schema.md](references/analysis-schema.md). Write the positioning before the detailed style fields: one decisive statement, one evidence-based description, and compact category/audience/emotion/promise labels. Use extracted colors as evidence, then merge perceptually similar colors into useful design tokens. Do not present algorithmic clusters as brand colors without checking the images.

Percentages must be either:

- measured from the scan and labeled as measured; or
- a visual recommendation such as `70 / 20 / 10`, labeled as a recommended allocation.

Do not fabricate precise coverage for semantic elements that the scanner cannot segment.

### 4. Render and verify

```powershell
python scripts/store_moodboard.py render --scan scan.json --analysis analysis.json --report store-visual-analysis.md --out game-store-moodboard.png --html game-store-moodboard.html
```

Open the PNG with `view_image`. Verify:

- the positioning statement and description are visible, specific, and consistent with the detailed analysis;
- all Chinese and Latin text renders correctly;
- no labels or thumbnails are clipped;
- swatch HEX values match their fills;
- the sample count matches the deduplicated scan;
- every conclusion is supported by visible evidence;
- the output remains readable when scaled down.

Return the written analysis first and the moodboard image second. Do not make the user open the working JSON files to understand the result.

If the renderer reports a missing CJK font, supply one with `--font <font-path>`. On Windows it automatically prefers Microsoft YaHei.

## Tool and dependency notes

- `scripts/store_moodboard.py` requires Python 3.9+ and Pillow.
- Prefer an existing environment that already contains Pillow. If missing, install only with user approval when installation is required.
- The renderer uses Pillow directly and does not require a browser, ImageMagick, or network access.
- Use `view_image` for visual QA; the scan JSON alone is not sufficient.

## Quality boundaries

- Exact duplicate detection does not detect near-duplicates, crops, or localized text variants. Note this when it affects the sample count.
- Dominant-color extraction is area-based and may overrepresent skies, water, or large neutral backgrounds.
- A polished key-art render and an in-engine screenshot may intentionally form separate lanes. Describe the bridge between them instead of forcing one style label.
- Keep game-specific findings in `analysis.json`; do not modify this skill to encode conclusions from one title.
